# Security model

What RDD reads, what it writes, where credentials live, and what to harden before exposing it to a production network.

For vulnerability reporting, see [SECURITY.md](../SECURITY.md) at the repo root.

## What RDD does on the wire

- ICMP echo (ping) to every host in the configured subnet.
- ARP table read (local cache, no network traffic generated by the read itself).
- Reverse DNS PTR queries (UDP/53 to the OS resolver).
- mDNS multicast (UDP 5353 → `224.0.0.251`) — one query burst per scan, ~3s passive listen.
- LLMNR multicast (UDP 5355 → `224.0.0.252`) — same pattern.
- NetBIOS name query (UDP/137) — unicast per unresolved host.
- Optional AXFR (TCP/53) to a configured authoritative DNS server.
- Optional TCP connect to 10 security-relevant ports per device (no payload, just SYN/RST or banner read on success).
- Optional HTTP/HTTPS GET for banner/title only.
- Optional UPnP SSDP M-SEARCH (UDP 1900 → `239.255.255.250`) and a follow-up HTTP GET to the LOCATION URL for the device-description XML.

The script never authenticates against a target. It does not exploit anything. The TCP banner grabs read what the server volunteers on connect — no credentials sent.

## Required privileges

The script runs without elevated privileges. ARP read, ping, multicast send, and TCP connect do not require admin on Windows 10/11/Server 2016+. Scheduled-task accounts only need write permission on `state.json`, `rdd-audit.csv`, and the OUI cache file.

## Files RDD writes

| File | Sensitivity |
|---|---|
| `config.json` | Contains SMTP credentials. **Restrict permissions.** |
| `state.json` | Contains MAC addresses, hostnames, IPs, operator-set labels. No credentials. |
| `rdd-audit.csv` | Append-only event log: scan start/done, device new/rogue/changed/absent, port allow/block, identity changes. MACs and hostnames; no credentials. |
| `oui.csv` | Public IEEE OUI database. Cached for 30 days. |
| `<lockfile>` | Empty exclusive-lock file to prevent concurrent scans. |

### Recommended file permissions for `config.json`

```powershell
# Lock down to SYSTEM + local admins; remove inherited ACEs.
icacls config.json /inheritance:r /grant:r "SYSTEM:F" "BUILTIN\Administrators:F"
```

This keeps SMTP credentials out of reach for non-admin users that might otherwise read the script directory.

## The `configured` safety gate

The unattended installer writes `"configured": false` to a fresh `config.json`. The main script refuses to run a normal scan until an operator reviews the file (SMTP settings in particular) and flips the flag to `true`. `-LearningMode`, `-ListDevices`, `-ApproveDevice`, `-RemoveDevice`, `-AllowPort`, and `-BlockPort` bypass the gate so the operator can set up the baseline before going live.

The gate is a usability safeguard, not a security boundary — it prevents an unattended-installed RDD from sending alerts to an unintended SMTP target before an operator has reviewed the config.

## AXFR authorisation

AXFR is denied by default on every modern DNS server. RDD's default is opt-in-with-default-on (`dnsZoneTransfer.enabled: true`) precisely because a denied request is harmless — one WARN log line and the cascade falls through to multicast resolvers. Authorising the RDD host on the DNS server (see [configuration.md → AXFR pre-fill](configuration.md#axfr-pre-fill-dnszonetransfer)) gives RDD a full IP→hostname map for the zone in one TCP request; the operator decides explicitly when to grant that.

## OUI database download

OUI lookup downloads `https://standards-oui.ieee.org/oui/oui.csv` once every 30 days, using the system proxy and a browser User-Agent. SHA-256 verification is not performed because IEEE does not publish a hash; if you need integrity guarantees here, host an internal mirror and point `ouiPath` at it.

## Releases

The release workflow signs assets with SHA-256 alongside the `.ps1` files. The unattended installer recipe in [deployment.md](deployment.md#unattended-install-rmm) verifies the updater's hash before executing it. The main script is then verified by the updater before installation.
